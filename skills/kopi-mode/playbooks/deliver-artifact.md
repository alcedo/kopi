# Deliver the Artifact

**Invoked at the end of every other playbook.** It owns the handover: the real file or record, the evidence behind it, and what stays open.

**Artifact.** Return the thing that was asked for. A plan, an outline, or a description of what you would build is not the deliverable when the user asked for a file, an event, a record, an update, or an analysis. One artifact per decision. When a request genuinely needs two, say what each one is for.

**Format and location.** Use the requested format. Use a provided template when one exists, otherwise a restrained neutral default, and do not invent branding. Write to the location the user named. Where none is named, write beside the source material inside the active workspace and state the path.

**Naming.** Name the artifact for its content and its as-of date, not for the process that made it. Keep the name stable across revisions of the same artifact so links and earlier references keep resolving.

**Evidence.** Ship the source pointers with the artifact. Keep the raw sweep, worker output, and intermediate notes out of it. Confidential evidence stays inside the audience the owning playbook authorized and stays out of every other deliverable in the same session.

**External writes.** Nothing leaves the workspace without authority. Apply the authority test in [permissions and writes](../references/permissions-and-writes.md), search for an existing equivalent record before creating one, then read the resulting record back and confirm its identifier, destination, participants, content, and state. Report partial success precisely and do not retry an uncertain write until duplicate risk is resolved.

**Verification.** Run [verify the deliverable](verify-deliverable.md) before this step. Deliver the verified artifact, not the draft you verified against.

**Reply.** Every playbook ends with a reply in this shape. Per-playbook lines name only what is unique to that playbook.

- The artifact with its path, identifier, or link.
- The decision it serves and what it concludes, in a few sentences for a consumer who will not open it.
- What you verified and how.
- Missing inputs, unresolved decisions, and contradictions left open.
- The pending external write and what it needs, when one is gated.
- The one best next action.

Do not pad the reply with restated steps, tool narration, or the artifact's table of contents.

**Open items.** Work left for other people routes to [follow through](follow-through.md). Work left for you to resume routes to [pause safely](pause-safely.md).
