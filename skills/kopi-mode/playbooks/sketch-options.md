# Sketch Options

**Invoked instead of asking a question that observation could answer.** It owns the cheap sample. The sketch is throwaway and the real artifact follows its owning playbook.

Speed beats polish here. This is the one playbook where a rough, partial, unsourced draft is correct output.

1. Name the fork the sketch exists to settle: which structure, which layout, which framing, which metric definition, which sequence. No fork means no sketch. Return to the owning playbook.
2. Classify the fork first. Anything you could observe by building or running something is not the user's to answer. A product, audience, confidentiality, or preference call is. Ask only for the second kind.
3. Build the smallest thing that shows the difference. Three slides, not a deck. One chart on a data sample, not the analysis. One agenda variant, one paragraph, one register column. Use placeholder content wherever real content would not change the answer.
4. Put the variants side by side under one label each so they compare in a single look.
5. Observe the thing you are deciding. Render the slides and look at them. Compute the metric both ways and check whether they separate. Read the two framings against the named audience. The observation is the evidence.
6. Report the variants, what you observed, and a recommendation. Say plainly that the sketch is throwaway and mark placeholder content as placeholder. Hand the chosen direction back to the owning playbook for the real build.

Never ship a sketch as the deliverable, and never carry placeholder numbers forward as evidence.
