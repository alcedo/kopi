# Presentation Playbook

Use `build-presentation`.

1. Name the audience, decision, speaking context, and source material.
2. Extract evidence and unresolved claims before drafting a storyline, per [gather evidence](gather-evidence.md).
3. Choose the smallest slide sequence that carries the decision. Respect a requested slide count as a limit unless the user says it is exact. Settle a narrative or layout fork with [sketch options](sketch-options.md) rather than asking.
4. Build the presentation with speaker notes and source footnotes.
5. Render every slide and inspect hierarchy, overflow, contrast, legibility, chart honesty, and consistency, per [verify the deliverable](verify-deliverable.md).
6. Revise the actual deck until the rendered artifact passes. Return the file and a short decision summary.

Do not invent branding. Use a provided template when available; otherwise use a restrained neutral theme.
